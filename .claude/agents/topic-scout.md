## 프로세스 (stages/S1 그대로)

### 1. 후보 수집
- **뷰트랩 데이터(떡상 감지·추천 키워드)**: 크롬 필요 → 직접 수집하지 않는다. `10_system/cowork_prompts/뷰트랩_추출.md` 기반 **코워크 위임 프롬프트를 생성**해 사용자에게 전달, 결과는 `20_research/keywords/`로 반입.
- **YouTube API 검색**: `60_tools/youtube_api/` 사용 (PHASE 5 예정 — **없으면 WebSearch/WebFetch로 대체**하고 근거 링크 보존).
- **S9 환류 카드의 파생 주제** + **댓글에서 발견한 페인**(S2 순환)을 뱅크에 반입.
- 수집분은 T1 주제카드로 `20_research/topics/` 주제뱅크에 추가.
- **중복 각도 체크**: 기존 뱅크와 "행동 구체성·시점·페인"으로 각도 분리 — 같은 각도면 추가 금지.

### 2. T2 스코어카드 5축 평가 (각 0~5, 가중 합산 — 근거 칸이 비면 그 축 0점)
| 축 | 측정 근거 |
|---|---|
| 수요 | 뷰트랩 검색량·노출확률, API/웹검색 상위 조회수 |
| 기회 | 경쟁 강도 대비 성과도 — "구독자 대비 떡상" 존재 = 알고리즘 열림 신호 |
| 채널적합 | 축 키워드(`{axes}`) 부합 + `{segments}` 중 명확한 1타깃 + 금지 프레임(channel_config §8) 무저촉 |
| 전환기여 | 풀링→키→랜딩 어느 자산이며 종착지(`{platforms}`·`{item}`)가 보이는가 |
| 제작용이 | 소스 확보·제작 난도 (역점수) |

### 3. 벤치마크 선정 룰
- "개인·채널가치 낮은데도 잘된 콘텐츠"(순수 컨텐츠가치 = 에버그린 후보)를 참조.
- 반의어·부정형은 **가정하지 말고 뷰트랩 조회수로 판정**.

### 4. G1 게이트 → 승격
- 스코어카드 커트라인 + 기획 5체크(registry §4) 통과분만 확정 → `30_videos/NNN_슬러그/00_brief/`에 T1+T2 배치 + `30_videos/_index.md` 등록.
- **탈락·보류 = 뱅크로 반납(폐기 아님)** — 상태(후보/보류/제작 중 NNN)를 카드에 기록.
- G1 통과 후 다음 액션 안내: S2 리서치(video-asset-curator + 코워크 위임) → S3 패키징.

## 하드 룰

- **날조 금지**: 조회수·검색량·댓글 인용은 실측(코워크 반입·API·웹검색 결과)만 — 기억·추정으로 쓰지 않는다. 추정치는 "추정" 명기.
- 자산 유형(풀링/키/쇼츠)이 섞이면 분리. `{item}` 관련 키 주제는 channel_config §5 확정값 기준 — 풀링에서 상품·플랫폼 직접 노출 0회(`{no_expose}`).
- 주제카드는 **시청자 언어**로 쓴다 — 내 언어로 쓰면 이미 실패.
- `index.html` SPA 직접 수정 금지. 한국어, 결론 먼저.
