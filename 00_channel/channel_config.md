# channel_config — 채널 변수 SSOT

> **이 파일이 채널의 모든 변수(정체성·아이템·시리즈·타깃·보이스)의 단일 진실 원천이다.**
> 파이프라인 문서(10_system/)·에이전트(.claude/agents/)는 아이템·시리즈·보이스를 **이 파일 참조로만** 언급한다 — 특정 아이템명·시리즈명을 시스템 문서에 하드코딩하는 것은 금지.
> 변수 표기: 문서에서 `{name}` `{axes}` 처럼 참조하면 본 파일의 해당 섹션 값을 뜻한다.
> 갱신: S0 채널 전략(분기 1회 점검) + 확정 이벤트 시. 반영 순서 = 본 파일 → `프로젝트_방향성.md` §1.1 → identity 문서. 작성: 2026-07-05 (전면개편 PHASE 2)

---

## 1. 확정 표면 자산 (즉시 사용 가능)

| 변수 | 값 |
|---|---|
| `{name}` 채널명 | **바이브코딩 치트키** 🔑 |
| `{handle}` 핸들 | `@바이브코딩치트키` |
| `{channel_id}` | `UCmlOkbbqe6Tl0S1F0NEDIrQ` |
| `{slogan}` 슬로건 | "AI를 잘 쓰는 사람들의 비밀은 프롬프트가 아니라 문해력입니다." |
| `{value_chain}` 가치사슬 | 읽고 이해하고 → AI로 만들고 → 바이브코딩으로 실행 |
| `{north_star}` 북극성 | 같은 AI를 써도 결과의 차이는 문해력·사고력에서 시작된다 |
| `{positioning}` 포지셔닝 | "단순 AI 툴 사용법 채널이 아니다" — 툴 강좌가 아니라 문해력·사고력·질문력 + 실행(제작)의 채널 |
| `{ssot}` 정체성 SSOT | `00_channel/identity/바이브코딩 치트키.MD` |

## 2. `{segments}` — 결 3그룹 (타깃)

| 결 | 정의 | 감정 코어 | 주력 자산 |
|---|---|---|---|
| ① 입문 | AI를 **안/못 쓰는** 사람 | 불안·소외감 → 안도 | 풀링 |
| ② 활용 | AI를 **쓰고 있는** 사람 | 정체감 → 성장 | 풀링·키 |
| ③ 심화 | AI를 **더 잘 쓰려는** 사람 (바이브코딩으로 직접 만들고 실행) | 호기심·깊이 → 성취 | 키·실전 |

- 단계별 주력 결: 단기 ② → 중기 ① → 장기 ③ *(방향성 §1.1 승계 — S0 분기 점검 시 재확인)*
- 결 호명 룰: 본문 중간 1개만, 마무리 챕터에서 3그룹 모두 + "그분들 옆자리"

## 3. `{axes}` — 콘텐츠 8축 (유입 → 토대 → 실행 3층)

| 층 | 축 |
|---|---|
| 유입 | AI 활용 · 바이브코딩 · AI 자동화 · 생산성 향상 |
| 토대 | 독서&문해력 · 사고력&질문력 |
| 실행 | AI 서비스 제작 · 실전 프로젝트 |

- 시스템 문서는 "축 키워드 1개"처럼 **개수 비의존 표현**을 사용한다 (구 "6축" 표기 금지 — 축 개편에 면역).
- 구 6축 문서 해석 시 변환: 정체성 SSOT §3 매핑표 참조.

## 4. `{platforms}` — 플랫폼 (수익화 종착지)

| 플랫폼 | URL | 역할 |
|---|---|---|
| 🌳 READTREE | `read.habitree.io` | 독서·문해력 축 종착지 |
| 🗺️ LINKMAP | `linkmap.biz` | 실행·연결 축 종착지 |
| 🧑‍💻 바이브코딩 무작정 따라하기 | `vibe.habitree.io` | 바이브코딩 실습 동선 |

## 5. `{item}` — 판매 아이템 로드맵

> ✅ **확정 (2026-07-06, 사용자 결정 D-010)** — 재검토 결과 구 1차 아이템 **이북리더기 복귀**. 기존 키 콘텐츠 산출물(30_videos 008 예정분) 재활용 가능.
> 유의: 신규 About·채널 키워드에는 이북리더기가 없으므로, 각 기획에서 **AI·문해력 ↔ 아이템 연결고리**(기획 5체크 ③)를 반드시 점검한다.

| 슬롯 | 값 | 상태 |
|---|---|---|
| `{item.primary}` 1차 아이템 | **이북리더기** | ✅ 확정 |
| `{item.ladder}` 확장 체인 | 이북리더기 → 책 관련 제품 → `{platforms}` (READTREE·LINKMAP 종착) | ✅ 확정 |
| `{no_expose}` 풀링 직접 노출 금지 목록 | 이북리더기 + `{platforms}` 전체 (풀링에서 상품·플랫폼 직접 노출 0회) | 룰 현행 |

- 시스템 문서(10_system/·CLAUDE.md·에이전트)는 여전히 아이템명 하드코딩 금지 — `{item}` 참조만. (아이템이 바뀌어도 시스템 문서는 한 글자도 안 바뀌게)

## 8. 금지 프레임·톤 룰 (전 스테이지 공통)

1. **AI 적대 프레임 금지** — "AI 무섭다/나쁘다" ✗ → "문해력 있는 사람이 AI를 더 잘 쓴다" 긍정 구도
2. **근거 없는 과장·낚시 금지** — '치트키'는 채널 브랜드 네임(**"진짜 치트키는 문해력"** 반전 프레임)으로만 사용. "이것만 알면 끝" 남발 금지 *(구 룰북의 "치트키 금지" 조항은 이 재정의로 대체됨)*
3. **개발자 전용화 금지** — 바이브코딩은 "코드를 몰라도 만든다"가 전제. 개발 지식 전제 화법 금지
4. **AI·문해력 진정성 점검** — About 약속("배우는 것에서 끝나지 않고 실행까지")을 콘텐츠 구조로 지킨다
5. 학자명·논문 직접 발화 금지 → 출처는 고정 댓글 / 1인칭 고백은 자기검열 없이
