## 2. 표준 명령 (사용자 → 시스템)

| 명령 | 동작 |
|---|---|
| `새 영상 시작: S1 <주제 후보>` | 주제카드+스코어카드 생성 → G1 → 통과 시 `30_videos/NNN_슬러그/` 생성 |
| `NNN 영상 S<K>부터 이어서` | 해당 영상 README 상태 보드 확인 → 스테이지 재개 |
| `주제뱅크 갱신` | S1 후보 수집 루프 (뷰트랩·API·환류 카드 반입) |
| `성과 리뷰 NNN` | S9 — T13·T14 작성 → 뱅크·룰 반영 |
| `룰 갱신: <스테이지> <내용>` | 해당 stages/ 문서 + guides 개정 (개정 이력 기록) |

## 3. 라우팅 규칙 (구 레지스트리 승계)

1. 트리거 매칭은 복수 가능 — 영상 단위 지시는 스테이지 순서(S1→S9)대로 분해.
2. 매칭 0개 또는 동급 충돌 → 사용자 1회 확인.
3. **기준 문서 gap 발견 시 산출물보다 기준 문서부터** 작성.
4. 기획 5체크(§4) 중 1개 이상 "아니오/모호" → 사용자 확인 후 진행.
5. 스테이지·에이전트 변동 시 **registry → CLAUDE.md 에이전트 맵 → 해당 stages/ 문서** 3곳 동기화 후 보고.
6. `{item}` 미확정 상태에서 키 콘텐츠 신규 기획 → 사용자 확인 필수 (channel_config §5 게이트).

## 4. 기획 5체크 (S1 게이트 공통 — 방향성 §6.1 승계)

1. 풀링인가 키인가? (성격 섞이면 분리)
2. 수익화 종착지가 명확한가? (`{platforms}`·`{item}` 중 무엇으로 가는가)
3. AI·바이브코딩 ↔ 문해력·책의 연결고리가 있는가?
4. READTREE·LINKMAP 연결 여지가 있는가?
5. 현재 학습 단계의 강의 개념이 적용됐는가?

## 5. 문서 계층

```
registry.md (라우팅)  →  stages/S<N>_*.md (스테이지 요약·게이트·링크 허브)
                       →  guides/ (상세 룰북 — 썸네일지침·편집기획·캡컷 스펙·뷰트랩 가이드 등)

                       →  checklists/ (G1~G5 + 승계 체크리스트)
                       →  cowork_prompts/ (크롬 필요 작업 위임 프롬프트)
```
