# 실행 플레이북 — 클로드코드 웹도구로 도입부 분석 (다운로드 없음)

> **이 문서의 역할**: [`README.md`](README.md)의 5단계 SOP를 **실제로 실행 가능한 도구 호출**로 옮긴 것.
> 캡처 엔진은 **브라우저 방식**(Chrome 웹도구) — 영상 다운로드 없이 실제 플레이어에서 시점 이동→일시정지→스크린샷.
> 자동화(yt-dlp+ffmpeg)는 채택하지 않음. 필요 시 README §7 폴백 참조.

## 2. Step 1 — 스크립트 추출 (3경로, 위에서부터 시도)

> 원칙: **영상을 통으로 보지 않는다.** 타임스탬프 스크립트부터 확보한다.

> ⚠️ **javascript_tool 제약(시연 검증)**: 이 도구는 REPL 평가라 **최상위 `return`·최상위 `await`가 모두 막힌다**. 코드는 반드시 **즉시실행함수 `(function(){ ... })()`** 로 감싸고, 비동기는 `fetch().then()`으로 처리해 결과를 `window.__x`에 저장 후 **다음 호출에서 읽는다**. 또한 **base64/대용량 바이너리 문자열 반환은 차단**된다(캡처 저장에 영향 — §4 참조).

### 경로 A (표준·1순위, 검증됨) — 자막 패널 DOM 수집

> 시연 결과 **가장 확실**. 캡션 직접 fetch(경로 B)는 토큰 요구로 빈 응답이 잦다.

```
1) navigate 로 영상 URL 열기 (광고 나오면 §4-0 광고 처리 먼저)
2) find("스크립트 표시 버튼 또는 Show transcript") → ref 확보
3) computer: scroll_to(ref) → left_click(ref)  ※ 한 번만! 두 번 누르면 토글로 닫힘
4) wait 4초 (세그먼트가 비동기로 채워짐)
5) javascript_tool 로 패널 열림+세그먼트 확인:
   document.querySelector('ytd-transcript-renderer') 및
   document.querySelectorAll('ytd-transcript-segment-renderer').length
   └ 아직 0이면 wait 더 주고 재확인 (닫혔으면 버튼 1회 재클릭)
6) 세그먼트 추출(IIFE):
```
```js
(function(){
  function toSec(t){var p=t.trim().split(':').map(Number);return p.length===2?p[0]*60+p[1]:0;}
  var segs=[].slice.call(document.querySelectorAll('ytd-transcript-segment-renderer'));
  var rows=segs.map(function(s){
    var t=(s.querySelector('.segment-timestamp')||{}).textContent||'';
    var x=(s.querySelector('.segment-text')||{}).textContent||'';
    return {sec:toSec(t), line:t.trim()+'  '+x.replace(/\s+/g,' ').trim()};
  });
  return rows.filter(function(r){return r.sec<=75;}).map(function(r){return r.line;}).join('\n');
})()
```
반환 줄을 `transcript.md`의 `§ 원본 스크립트`에 붙여넣는다. (자동생성 자막은 오타가 많으니 `§정리`에 교정본을 둔다.)

### 경로 B (파워, 되면 최고지만 자주 실패) — 캡션 트랙 fetch

빠르고 타임스탬프가 정확하지만, **시연에서는 `fetch(baseUrl+'&fmt=json3')`가 빈 본문(`Unexpected end of JSON input`)을 반환**했다(YouTube `pot` 토큰 요구 추정). 되는 환경에서만 사용하고, 안 되면 즉시 경로 A로:

```js
// 1콜: 시작(결과를 window.__cap 에 저장) — IIFE, await 미사용
(function(){window.__cap='PENDING';try{var r=window.ytInitialPlayerResponse;var tr=(r&&r.captions&&r.captions.playerCaptionsTracklistRenderer&&r.captions.playerCaptionsTracklistRenderer.captionTracks)||[];if(!tr.length){window.__cap='NO_CAPTIONS';return;}var p=tr.find(function(t){return t.languageCode==='ko';})||tr[0];fetch(p.baseUrl+'&fmt=json3').then(function(x){return x.json();}).then(function(j){window.__cap=(j.events||[]).filter(function(e){return e.segs;}).map(function(e){var s=Math.floor(e.tStartMs/1000);return Math.floor(s/60)+':'+String(s%60).padStart(2,'0')+'  '+e.segs.map(function(g){return g.utf8;}).join('').replace(/\n/g,' ').trim();}).join('\n');}).catch(function(e){window.__cap='ERR:'+e.message;});}catch(e){window.__cap='ERR:'+e.message;}})()
// 2콜(2초 뒤): window.__cap 읽기 → 'ERR:'/'PENDING'이면 경로 A로 폴백
```

## 3. Step 2 — 맥락 분석 → 구간 선정 (자동 초안 규칙)

`transcript.md`를 읽고 캡처할 구간만 고른다. **영상 전체 프레임을 찍지 않는다.**

### 3-1. 주요 구간 (반드시 캡처) — 자동 탐지 규칙

| 트리거 | 탐지 방법 |
|---|---|
| 첫 컷 (0:00) | 항상 포함 |
| 첫 발화 | transcript 첫 비어있지 않은 라인 시각 |
| 의미 전환 | 발화에 `그런데/하지만/사실/근데/문제는` 포함된 라인 |
| 숫자·키워드 | `\d+%`, `\d+가지`, `\d+권`, 8축 키워드 매칭 라인 |
| 도입부 마지막 | 0:55~1:00 마지막 라인 |
| 인물·화면 전환 | 스크립트로 불명 → 희박 샘플링으로 보완 |

### 3-2. 희박 구간 5~10초 샘플링 (스크립트가 빈 구간)

> **희박 구간** = 연속 발화 없이 5초+ 공백(=B-roll·음악·침묵).

| 공백 길이 | 샘플 간격 |
|---|---|
| 5~15초 | 5초마다 1장 |
| 15초+ | 10초마다 1장 |
| 3초 미만 | 생략 |

예: 0:12~0:28 공백 → 0:12, 0:17, 0:22, 0:27 (4장).

**산출물**: `transcript.md` 하단 `§ 구간 선정표`를 채운다(주요/희박, 캡처 시점, 라벨, 파일명).

## 4. Step 3 — 브라우저 캡처 (구간별 반복)

> 🔴 **시연 핵심 결론**: 이 환경에서는 **브라우저 캡처를 이미지 파일로 자동 저장할 수 없다**(§4-4). 화면 **열람·분석은 가능**(탭이 포그라운드일 때). 파일이 필요하면 **수동 캡처 가이드**(&t= URL)로 사용자가 저장한다.

### 4-0. 광고 처리 (검증됨)

영상을 열면 광고가 먼저 뜰 수 있다. 광고 중에는 `video.duration`이 **본편이 아니라 광고 길이**(예: 91초)다.

```
1) javascript_tool: var b=document.querySelector('.ytp-ad-skip-button-modern,.ytp-ad-skip-button,.ytp-skip-ad-button,.ytp-ad-skip-button-container button'); b&&b.click();
   └ 버튼 selector가 안 먹으면 screenshot 후 '건너뛰기' 좌표를 computer left_click
2) wait 후 재확인: document.querySelector('.ad-showing,.ytp-ad-player-overlay') 가 null 이고
   video.duration 이 본편 길이로 바뀔 때까지 1~2회 반복
```

### 4-1. 정밀 이동 + 일시정지 — `javascript_tool` (IIFE, `return` 금지)

```js
(function(){var v=document.querySelector('video');if(!v)return 'NO_VIDEO';v.pause();v.currentTime=17;return {ct:+v.currentTime.toFixed(2),paused:v.paused};})()
```

### 4-2. 시크·렌더 상태 확인 (⚠️ 탭 포그라운드 필수)

```js
(function(){var v=document.querySelector('video');return {t:+v.currentTime.toFixed(2),paused:v.paused,ready:v.readyState,hidden:document.hidden};})()
```

> **검증된 함정**: `document.hidden===true`(탭이 백그라운드)면 크롬이 프레임을 디코드하지 않아 `ready`가 1에 머물고 **스크린샷이 30초 타임아웃(렌더러 정지)**된다. 캡처 전 반드시 **해당 탭을 포그라운드로** 둔다. `ready>=2` & `paused=true` & `t≈목표` 확인 후 진행.

### 4-3. 프레임 열람 — `computer` screenshot (seek와 **분리** 호출)

- **seek와 같은 batch에 스크린샷을 넣지 말 것** — 시크 직후 디코드로 캡처가 자주 타임아웃. seek(JS) → (별도 호출) screenshot 순서로.
- 스크린샷 이미지가 분석가(Claude)에게 인라인 반환되어 **화면 분석은 가능**(번인 자막·컷 유형·구도 판독).

### 4-4. 저장 방식 (🔴 검증됨 — 환경별 분기)

| 방법 | 결과(본 환경 시연) | 사용 |
|---|---|---|
| 캔버스 `toDataURL`→base64 반환 | **차단**(base64 컨텍스트 반입 불가) | ❌ |
| `computer` screenshot `save_to_disk:true` | **무효**("not persisted to disk in this session") | ❌ |
| sandbox `yt-dlp`+`ffmpeg -ss` 프레임 추출 | **불가**(프록시 403, YouTube 미도달) | ❌(이 환경) |
| **수동 캡처**(`Win+Shift+S`)→`captures/`에 저장 | ✅ 동작 | ✅ **권장** |

**자동 저장이 가능한 다른 환경**이라면(참고용):
- base64 반환이 허용되면: 캔버스 추출(아래) → 반환 base64를 sandbox에서 `base64 -d`로 `captures/*.jpg` 저장. *(YouTube는 MSE blob 재생이라 캔버스 CORS 오염 없음 — 시연에서 `toDataURL` 자체는 성공.)*
- sandbox에서 YouTube 도달이 가능하면: `yt-dlp --download-sections "*0-75" -f mp4` → `ffmpeg -ss T -i ... -frames:v 1 captures/파일.jpg`.

```js
// (참고) 캔버스 프레임 → base64. 단, 본 환경은 반환이 차단됨.
(function(){var v=document.querySelector('video');var W=854,H=Math.round(W*v.videoHeight/v.videoWidth);var c=document.createElement('canvas');c.width=W;c.height=H;c.getContext('2d').drawImage(v,0,0,W,H);return c.toDataURL('image/jpeg',0.6).split(',')[1];})()
```

**→ 결론**: 본 환경의 표준 절차는 **(분석가가 화면을 열람해 분석) + (사용자가 수동 캡처로 파일 저장)**. 각 영상 폴더에 `captures/_수동캡처_가이드.md`(시점별 `&t=` URL·파일명)를 생성해 둔다.

| ★ 자막 패널이 안 열림/세그먼트 0 | 클릭 2회로 토글되어 닫힘 / 비동기 로딩 | `find`로 버튼 ref→**1회만** 클릭, wait 4초+, `ytd-transcript-renderer` 확인 |
| ★ `ERR:Unexpected end of JSON input` | 캡션 fetch가 빈 본문(토큰 요구) | 경로 B 포기 → **경로 A(패널)** |
| ★ `ReferenceError: await is not defined` / `Illegal return` | 최상위 await·return 사용 | **IIFE로 감싸고** then()+window 저장 패턴 |
| ★ 스크린샷 30초 타임아웃(렌더러 정지) | 탭이 **백그라운드**(`document.hidden`) | 탭을 **포그라운드**로, seek와 스크린샷 **분리** 호출 |
| ★ base64 반환이 `[BLOCKED]` | 대용량 바이너리 컨텍스트 차단 | 자동 저장 포기 → **수동 캡처 가이드** |
| ★ `save_to_disk` 효과 없음 | 본 세션 미저장 | 동일 — 수동 캡처 |
| ★ 광고 재생(`duration`이 광고값) | 프리롤 광고 | §4-0 스킵 루프 |
| `NO_VIDEO` | 플레이어 미로드 | 2~3초 대기 후 재시도 |
| 연령제한·로그인 벽 | 콘텐츠 게이트 | 사용자 로그인 세션 필요 — 확인 요청 |
| 쿠키/동의 팝업 | EU 동의창 | 동의 클릭 후 진행 |

> ✅ **정정**: 캔버스 `toDataURL`은 YouTube(MSE blob 재생)에서 **CORS 오염 없이 성공**한다. 막히는 것은 **base64를 도구 결과로 반환**하는 단계다. 따라서 "스크린샷이 정답"이 아니라, **이 환경에선 자동 저장 자체가 불가 → 수동 캡처**가 답이다.
