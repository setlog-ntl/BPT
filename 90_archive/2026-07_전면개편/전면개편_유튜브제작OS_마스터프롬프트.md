## A.3 바꿀 것 (개편의 3대 방향)

1. **문서 유형 중심 → 영상 단위 중심.** 지금은 영상 1편의 기획·대본·썸네일·편집·메타데이터가 `대본/`, `docs/keycontent/`, `편집/`, `자동화편집/03_프로젝트/`, `유튜브 기본정보/`에 분산된다. 앞으로 영상 1편 = 폴더 1개(`30_videos/NNN_슬러그/`)에 생애주기 전체가 담긴다.
2. **주제 하드코딩 → 변수화.** "이북리더기", 특정 시리즈명이 룰북과 에이전트 정의에 박혀 있다. 판매 아이템·시리즈·타깃은 `00_channel/channel_config.md` 한 곳에서만 정의하고, 파이프라인 문서는 이를 참조만 한다. 새 아이템·새 시리즈가 생겨도 시스템 문서는 한 글자도 안 바뀌게 한다.
3. **분산 룰북 → 스테이지 레지스트리.** `대본/_기획기준/`, `편집/_기획기준/`, `docs/claude-code/prompts/`, `자동화편집/04_프롬프트/`, `.claude/agents/` 5곳에 흩어진 규칙을 **파이프라인 스테이지 S0~S9 문서 10개**(`10_system/stages/`)로 재편성한다. 내용은 승계, 조직만 재배열.

## A.4 절대 준수 하드 룰 (위반 시 즉시 중단하고 사용자에게 보고)

1. **SPA 보존·수리.** `index.html`(약 7,888줄/452KB, hash 라우팅)은 이동·개명 금지. 2026-07-05 실측 기준 index.html의 외부 참조는 두 부류다:
   - **유효 링크 (원위치 보존이 기본, 이동 시 같은 커밋에서 링크 일괄 갱신+링크체커 0건)**: `docs/item/아이템선정_워크시트.html` · `docs/item/최종선정10개.md` · `docs/item/bizpt-item-categories-2026-04-28.json` · `대본/_기획기준/대본기획_기준.md` · `대본/_기획기준/30초_후크_룰_체크리스트.md` · `대본/풀링컨텐츠/005_AI시대 살아남는/` 하위 4개(통합 HTML·대본·브리프·강의적용)
   - **이미 깨진 링크 (PHASE 4에서 수리 의무)**: ① `docs/keycontent/*` 5개 — 폴더 자체가 삭제됨(산출물은 `대본/키컨텐츠/이북리더기_자기계발/` 등으로 진화) ② `대본/풀링컨텐츠/평생 안읽던 사람이…/` 3개 — 폴더가 `001_평생 안읽던 사람이…`로 리네임됨
   - ※ CLAUDE.md §4.1의 "변경 금지 4파일" 목록도 keycontent 등 사어(死語)를 포함한다 — 문서가 현실보다 낡았다. **PHASE 0에서 전 링크를 재추출해 유효/사망을 판정**하고, 이 판정이 이후 모든 이동 결정의 근거가 된다.
2. **raw ≠ 정리본.** `raw/`(강의 필사·원본)는 구조·내용 불변. 정리본만 재배치 대상.
3. **readingtree 본문 금지.** bizpt 안에 readingtree 본문 정리 금지. 인덱스(`readingtree_연계.md`) 참조만.
4. **파괴 금지.** 어떤 PHASE에서도 파일 **삭제는 없다**. 제거 대상은 전부 `90_archive/`로 이동. git 브랜치(`overhaul/youtube-os`)에서 작업하고 PHASE 단위로 커밋. `.credentials/`, `.env`는 절대 건드리지 않는다.
5. **게이트 프로토콜.** 각 PHASE 종료 시 §G.2 양식으로 보고하고 사용자 승인 후 진행. 승인 없이 다음 PHASE의 파일 조작 금지.
6. **톤 룰 승계.** 새로 쓰는 모든 문서에 A.2의 톤 룰 적용.
7. **원본 참고.** 이 프롬프트의 저장소 스냅샷(§부록2)은 2026-07-05 기준이다. 실행 시점의 실제 상태와 다르면 **실제 상태가 우선**하며, 차이를 PHASE 0 보고서에 명시한다.

- 번호 `NNN`은 기존 풀링 번호 001~007(실사용 중)을 그대로 승계하고, 신규는 008부터 채널 전체 일련번호로 확장.
- 통합 HTML(1페이지 열람용)은 유지하되 **원천 데이터는 항상 md** — HTML은 md에서 생성하는 뷰로 취급.
- 1,500줄/40KB 이상 HTML은 멀티페이지 허브 구조 표준(승계) 적용.

# 부록 1 — 대형 채널 기획 원칙 (모든 스테이지 문서 상단에 "왜"로 인용)

1. **패키징 퍼스트**: 아이디어→제목·썸네일→대본 순. 클릭되지 않을 영상은 만들지 않는다.
2. **CTR × AVD**: 알고리즘의 본질은 두 숫자. 모든 산출물은 둘 중 하나에 복무해야 한다 — 어느 쪽에도 복무하지 않는 작업은 버린다.
3. **아이디어 깔때기**: 다량 발굴(주제뱅크) → 데이터 스코어링 → 소수 정예 제작. 발굴과 제작을 분리한다.
4. **리텐션 설계**: 후크 30초 → 중간 re-hook → 페이오프 지급. 대본은 긴장 곡선의 설계도다.
5. **1 video = 1 project**: 영상 1편의 전 생애가 폴더 1개에. 흩어진 산출물은 반복 가능한 시스템이 되지 못한다.
6. **데이터 환류**: 발행 후 지표가 다음 주제·패키징·대본 룰을 갱신한다. 루프가 닫혀야 복리가 생긴다.
7. **포맷화·시리즈화**: 성공한 구조는 즉시 템플릿으로 승격(006 표준 골격 사례). 매번 백지에서 시작하지 않는다.
8. **시청자 언어**: 제목·후크·썸네일 문구는 창작하지 않고 댓글에서 채굴한다.
