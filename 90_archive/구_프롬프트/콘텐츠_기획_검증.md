# 콘텐츠 기획 검증

## 목적
이미 작성된 콘텐츠 기획서(풀링/키/랜딩 어느 것이든)를 **3대 기둥 + 의사결정 체크리스트**로 점검해 약점·맹점을 찾고 개선안을 제시.

## 입력 (사용자가 제공)
- **검증할 기획서 경로**: 예) `docs/keycontent/키_킨들_단말기_추천.md`
- **(선택) 특별히 점검받고 싶은 항목**: 예) "전환 동선" / "책 진정성" / "수익 역산"

## 사전 참조
1. `CLAUDE.md` (루트)
2. `프로젝트_방향성.md` 전체 — 특히 §3, §5, §6, §6.4
3. 검증 대상 기획서가 인용한 강의 정리본 (`docs/lectures/...`)
4. `docs/reference/01_용어집.md`, `docs/reference/readingtree_연계.md`

## 작업 절차
1. **기획서 통독** — 의도와 현재 구조 파악.
2. **3대 기둥 정렬 점검**:
   - ① 비즈니스PT 학습 적용: 어떤 강의 개념이 어디에 적용됐는가? 누락된 개념은?
   - ② 책 중심 콘텐츠: 좋아하는 책에 대한 진정성이 살아있는가? 클릭베이트로 변질 위험?
   - ③ readingtree 연계: 직간접 연결 고리가 있는가? 강제 연결 아닌가?
3. **의사결정 체크리스트(§6.1) 5개 적용**:
   - 풀링/키 성격 분리 / 수익화 종착지 / 책 연결 / readingtree 연결 / 강의 개념 적용
4. **단계별 우선순위(§6.4) 정합성**:
   - 현재 단계(단기 ② / 중기 ③ / 장기 ①)에 맞는 우선순위로 설계됐는가?
5. **퍼널 논리 점검**:
   - 풀링이면 → "탐색 유입 → 신뢰 → 다음 콘텐츠" 흐름이 자연스러운가
   - 키면 → "검색 유입 → 비교/검토 → CTA → 전환" 흐름이 자연스러운가
   - 단가·전환율·트래픽 역산이 합리적인가
6. **약점·맹점 정리** + **개선안 제시** (3~5개, 우선순위 표시).

## 산출물 형식 / 저장 위치
- 검증 결과는 **별도 파일로 저장하지 않고 대화 결과로 응답**하는 것이 기본.
- 단, 사용자가 "기록으로 남기자"고 하면 `docs/keycontent/_review/<원본파일명>_review_<날짜>.md`에 저장.

산출물 형식:
```markdown
# <기획서 제목> 검증 결과 (2026-XX-XX)

## 한 줄 평
...

## 3대 기둥 정렬
- ① 학습 적용: ...
- ② 책 진정성: ...
- ③ readingtree: ...

## 의사결정 체크리스트
| # | 항목 | 통과 여부 | 메모 |
|---|---|---|---|
| 1 | 풀링/키 분리 | ✅/⚠️/❌ | ... |
| 2 | 수익화 종착지 | ... | ... |
| 3 | 책 연결 | ... | ... |
| 4 | readingtree 연결 | ... | ... |
| 5 | 강의 개념 적용 | ... | ... |

## 약점·맹점 (우선순위 순)
1. **[P0]** ...
2. **[P1]** ...

## 개선안
- ...
```

## 완료 체크리스트
- [ ] 3대 기둥 모두에 대해 한 줄 이상 평가했는가
- [ ] 의사결정 체크리스트 5개 모두 점검했는가
- [ ] 약점·맹점에 우선순위 표시(P0/P1)를 붙였는가
- [ ] 개선안이 실행 가능한 수준으로 구체적인가 (추상적 표현 금지)
