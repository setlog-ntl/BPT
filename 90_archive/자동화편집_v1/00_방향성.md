# 자동화편집 — 방향성 문서

> 이 문서는 `자동화편집/` 하위 모든 작업의 단일 진실 원천(SSoT).
> 작성: 2026-05-03 / 작성자: 최동혁 + Claude

---

## 1. 한 줄 정의

**bizpt 콘텐츠(풀링·키·랜딩) 영상 제작을 "지침→템플릿→자동 패키지" 3단 체계로 고도화하여, 점진적으로 캡컷 편집 부담을 최소화하는 워크스페이스.**

## 2. 왜 자동화편집인가 (북극성)

- 콘텐츠 모델(풀링→키→랜딩)이 자리 잡으려면 **꾸준한 발행 속도**가 필요하다.
- 매번 "백지에서 기획→자료수집→편집"을 반복하면 4주차 이후 풀링 콘텐츠 양산 단계에서 막힌다.
- 따라서 **"한 번 잘 만든 패턴은 자산화한다"**가 본 프로젝트의 핵심 운영 원칙.

## 3. 3축 체계

| 축 | 이름 | 정의 | 위치 |
|---|---|---|---|
| 축1 | **템플릿(Template)** | 영상 유형별 반복 사용 가능한 구조(자막 스타일, 인트로/아웃트로, 타임라인 패턴) | `01_템플릿/` |
| 축2 | **자산(Asset)** | 인트로·아웃트로·비롤·효과음·배경음악·썸네일 프레임 등 재사용 미디어 | `02_자산_라이브러리/` |
| 축3 | **자동화(Automation)** | 텍스트 입력 → 자료수집 → 스크립트 → 캡컷 패키지 자동 생성 워크플로우 | `04_프롬프트/` + `03_프로젝트/` |

이 셋이 모일 때 비로소 **"수동 import + 자료 패키지 자동 생성"** 방식이 작동한다.

## 4. 캡컷 연동 원칙

사용자가 선택한 방식: **수동 import + 자료 패키지 자동 생성**.

```
[Claude 자동화]                              [사용자 수동]
텍스트/주제 입력                                 │
   ↓                                          │
관련 자료(이미지·영상·인용·통계) 수집·정리          │
   ↓                                          │
스크립트 + 자막(SRT) + 편집 가이드 생성            │
   ↓                                          │
03_프로젝트/<제목>/03_캡컷_패키지/ 폴더 완성       │
                                              ↓
                                   캡컷에서 import → 편집 → 출력
```

**이유**: 캡컷 .draft 직접 조작은 버전 의존성이 크고 위험. 사용자가 1차 편집 결과물을 보면서 미세조정할 여지를 남기는 것이 현실적.

**자동화 범위 (단계적 확장)**:
- **Phase 1 (지금)**: 자료 수집 + 스크립트 + 편집 가이드 자동 생성
- **Phase 2 (자산 누적 후)**: 인트로/아웃트로/비롤 자동 매칭 추천
- **Phase 3 (장기)**: FFmpeg/Python으로 1차 컷 편집까지 자동 → 캡컷에서 마감

## 5. 영상 유형별 자동화 우선순위

| 유형 | 자동화 난이도 | 우선순위 | 근거 |
|---|---|---|---|
| **풀링 (쇼츠/릴스)** | 낮음 (구조 단순) | **★★★ 최우선** | 양산이 핵심. 자동화 효과 최대 |
| **키 (본 영상)** | 중간 | ★★ | 길이 길지만 챕터 구조화 가능 |
| **랜딩/세일즈** | 높음 (커스터마이징 多) | ★ | 건수 적음. 템플릿화만 우선 |

→ 따라서 **풀링 콘텐츠 자동화 파이프라인을 가장 먼저 완성**한다.

## 6. bizpt 본 프로젝트와의 관계

| 구분 | bizpt 본 프로젝트 | 자동화편집 (본 폴더) |
|---|---|---|
| 역할 | 전략·기획·학습·콘텐츠 결정 | 영상 제작 실행·자산 관리·자동화 |
| 주요 산출물 | 강의 정리, 콘텐츠 기획서, 시장 분석 | 영상 패키지, 템플릿, 자산 라이브러리 |
| 입력 | 사용자 학습·아이디어 | bizpt 본 프로젝트의 기획서 |
| 출력 | 콘텐츠 기획 결정 | 캡컷에 import 가능한 패키지 |

**연결 지점**:
- bizpt `docs/keycontent/` 의 기획서 → 자동화편집 `03_프로젝트/` 의 입력
- 자동화편집 `02_자산_라이브러리/` 는 bizpt 콘텐츠 모델(풀링/키/랜딩) 기준으로 분류

## 7. 의사결정 체크리스트 (작업 전 점검)

새 영상 작업/템플릿/자산을 추가하기 전 다음을 점검:

1. 이 영상은 풀링/키/랜딩 중 **어디에 속하는가**?
2. 기존 **템플릿/자산으로 70% 이상 커버**되는가? (안 되면 → 새 자산 등록 후 진행)
3. **bizpt 본 프로젝트의 기획서**가 입력으로 존재하는가? (없으면 본 프로젝트에서 먼저 작성)
4. 결과물이 **재사용 가능한 자산**으로 추출될 여지가 있는가? (있으면 작업 후 카탈로그에 등록)
5. 캡컷 편집 가이드가 **다음 사람(또는 미래의 나)도 따라 할 수 있게** 작성되었는가?

## 8. 단계별 로드맵

### Phase 0: 기반 구축 (이번 세션) ← **현재**
- 폴더 구조, 워크플로우 정의, 표준 프롬프트 5종, 캡컷 패키지 스펙

### Phase 1: 풀링 첫 영상 (4주차)
- 1번 풀링 영상을 **이 시스템으로 끝까지** 만들어보면서 시스템 검증·보정
- 발생한 자산은 즉시 라이브러리에 등록

### Phase 2: 풀링 5~10편 양산
- 동일 템플릿 반복 적용. 자산 라이브러리 누적
- 워크플로우 병목 지점 기록 → 자동화 우선순위 재조정

### Phase 3: 키·랜딩 영상 템플릿 확장
- 키 콘텐츠 본 영상용 템플릿 추가
- readingtree 연계 랜딩 영상 템플릿 추가

### Phase 4 (장기): FFmpeg/Python 1차 컷 편집 자동화
- 자료 충분히 모였을 때만 진입. 그 전엔 수동 import가 더 빠름.

## 9. 하드 룰

- **bizpt 본 프로젝트 콘텐츠 결정은 여기서 하지 않는다.** 기획·전략은 bizpt 본 폴더에서.
- **원본 미디어 파일은 자산 라이브러리에 직접 두지 않는다.** 카탈로그(메타데이터)만 자산 라이브러리에, 실제 파일은 별도 미디어 저장소 경로를 참조.
  - 이유: git 저장소 비대화 방지. (나중에 .gitignore 정책 결정)
- **각 영상 프로젝트 폴더는 발행 후 보존한다.** 자동화 패턴 학습용 데이터.
- **편집 가이드는 한국어, 시간 순서대로, 명령형으로 작성.** 모호한 표현 금지("적당히", "느낌 있게" 등).
