# 영상 유형별 표준 워크플로우

> 새 영상 작업을 시작할 때 가장 먼저 보는 문서.
> 유형 결정 → 해당 절(§)로 이동 → 단계별 진행.

---

## 공통 0단계: 입력 정리

영상 작업의 **모든 입력**은 다음 셋 중 하나 형태로 들어온다:

| 입력 형태 | 예시 | 다음 액션 |
|---|---|---|
| **주제 텍스트** | "데미안의 자기 발견 3단계를 풀어주는 쇼츠" | 04_프롬프트/자료수집_명령.md → 04_프롬프트/풀링_기획서_생성.md |
| **bizpt 기획서 링크** | `bizpt/docs/keycontent/2026-05-10_데미안_쇼츠.md` | 위 기획서를 입력으로 04_프롬프트/캡컷_패키지_생성.md |
| **참고 자료 묶음** | URL/이미지/PDF 다수 | 04_프롬프트/자료수집_명령.md(정리만) → 사용자와 기획 합의 → 패키지 생성 |

→ 입력 형태가 정해졌으면 **유형 결정** 단계로.

---

## 공통 1단계: 유형 결정

| 질문 | Yes → | No → |
|---|---|---|
| Q1. 길이가 60초 이하인가? | **풀링** (§A) | Q2 |
| Q2. 특정 상품·서비스 전환을 직접 유도하는가? | **랜딩** (§C) | **키** (§B) |

※ 모호하면 **풀링**으로 시작 (가장 가벼운 자동화 경로).

---

## §A. 풀링 (쇼츠/릴스) 워크플로우

**핵심**: 양산이 목표. 자동화 효과 최대.

```
[0] 03_프로젝트/YYYY-MM-DD_풀링_<제목>/ 폴더 생성
       ↓
[1] 자료수집     → 04_프롬프트/자료수집_명령.md 실행
       ↓        → 결과: 02_자료수집/ 채워짐
[2] 기획서 작성  → 04_프롬프트/풀링_기획서_생성.md 실행
       ↓        → 결과: 00_기획서.md
       ↓        → ※ 사용자 검토 1회 (후킹·CTA 적절성)
[3] 스크립트     → 기획서 기반 30~60초 스크립트 자동 생성
       ↓        → 결과: 01_스크립트.md (시간코드 0~60초)
[4] 캡컷 패키지  → 04_프롬프트/캡컷_패키지_생성.md 실행
       ↓        → 결과: 03_캡컷_패키지/ 전체
       ↓          ├─ 편집_가이드.md (시간 순서대로 명령형)
       ↓          ├─ 자막.srt
       ↓          ├─ 사용자산.md (인트로/배경음악/효과음 ID 매칭)
       ↓          └─ 배경음악_지정.md
[5] 썸네일       → 04_프롬프트/썸네일_카피_생성.md 실행
       ↓        → 결과: 04_썸네일/카피_초안.md (3안)
       ↓        → ※ 사용자가 1안 선택 + 이미지 합성
[6] 메타데이터   → 제목·설명·태그 작성
       ↓        → 결과: 05_메타데이터/ 채워짐
[7] 캡컷 import → ★ 사용자 작업: 03_캡컷_패키지/ 전체를 캡컷으로 import
       ↓                       → 편집 가이드 따라 5~15분 마감 편집
       ↓                       → 영상 출력
[8] 발행체크    → 05_체크리스트/발행전_최종점검.md 통과 후 업로드
```

**소요 시간 목표**: [1]~[6] Claude 작업 30분 / [7] 사용자 편집 15분.

## §B. 키 (본 영상) 워크플로우

**핵심**: 챕터 구조화로 길이 부담 분산.

```
[0] 03_프로젝트/YYYY-MM-DD_키_<제목>/ 폴더 생성
       ↓
[1] 자료수집     → 04_프롬프트/자료수집_명령.md (depth=high)
       ↓        → 결과: 02_자료수집/ 깊이 있게 채움
[2] 챕터 개요    → ★ 사용자와 합의 단계
       ↓        → 4~6개 챕터 제목 + 각 챕터 핵심 메시지 1줄
       ↓        → 결과: 00_기획서.md (챕터 구조 포함)
[3] 챕터별 스크립트 → 04_프롬프트/키_스크립트_생성.md 챕터마다 실행
       ↓           → 결과: 01_스크립트.md (챕터별 시간코드)
       ↓           → 챕터마다 마이크로 CTA 1개씩
[4] 캡컷 패키지  → 04_프롬프트/캡컷_패키지_생성.md (mode=long)
       ↓        → 결과: 03_캡컷_패키지/
       ↓          ├─ 편집_가이드.md (챕터별 섹션 + 챕터 인디케이터 자막 지정)
       ↓          ├─ 자막.srt (챕터별 분리 가능)
       ↓          ├─ 사용자산.md
       ↓          └─ 배경음악_지정.md (챕터마다 다른 배경음악 가능)
[5] 썸네일       → 키 영상은 썸네일 비중 더 큼 → 3안 + 사용자 결정
[6] 메타데이터   → 챕터 타임스탬프 포함한 설명란
[7] 캡컷 import → 사용자 마감 편집 (목표 30~60분)
[8] 발행체크
```

**소요 시간 목표**: [1]~[6] Claude 작업 1~2시간 / [7] 사용자 편집 30~60분.

## §C. 랜딩/세일즈 워크플로우

**핵심**: 매번 커스터마이징 多. 템플릿화는 "구조"만, 카피는 매번 새로.

```
[0] 03_프로젝트/YYYY-MM-DD_랜딩_<제목>/ 폴더 생성
       ↓
[1] 입력 정리    → 대상 상품/서비스, 타깃 페르소나, 핵심 차별점, 가격
       ↓
[2] 4단 구조 적용 → 문제(Problem) → 약속(Promise) → 증거(Proof) → CTA
       ↓        → 결과: 00_기획서.md (4단 각 30~60초)
       ↓        → ※ 사용자 검토 필수 (오버 프로미스 점검)
[3] 스크립트     → 사용자가 직접 카피 검토·수정
       ↓        → Claude는 초안만 제공
[4] 캡컷 패키지  → 04_프롬프트/캡컷_패키지_생성.md (mode=landing)
       ↓        → 03_캡컷_패키지/편집_가이드.md 에
       ↓          "Proof 구간은 실제 사용자 후기 자막 강조" 같은 지시 포함
[5] 썸네일       → 상품 시각 + 핵심 약속 1줄
[6] 메타데이터   → 설명란에 명확한 랜딩 URL
[7] 캡컷 import → 사용자 편집 + 사용자 본인 출연 컷 추가 가능성 高
[8] 발행체크    → ★ 광고 표기·과장 표현 점검 필수
```

**소요 시간 목표**: [1]~[6] Claude 작업 1시간 / [7] 사용자 편집 30~90분.

---

## 모든 유형 공통 [9]: 발행 후 회고 (1주 후)

발행 1주일 후 다음 항목 기록 → `05_체크리스트/발행후_회고.md`:

- 조회수·노출·CTR (유튜브 스튜디오)
- 어느 구간에서 시청 이탈이 컸는가
- 워크플로우 [1]~[8] 중 병목 단계
- 다음 영상에 반영할 패턴 1~2개

→ 패턴이 누적되면 → 새 자산/템플릿으로 추출 → 자동화 수준 상승.

---

## 워크플로우 갱신 정책

이 문서는 영상 5편마다 1회 갱신 검토. 발행 후 회고 5건이 모이면 패턴이 보인다.
갱신 시 [`00_방향성.md`](00_방향성.md) 의 단계별 로드맵도 함께 점검.
